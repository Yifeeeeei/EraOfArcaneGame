# 固定手牌 dock 与三步防御

基线 `82d7c9044d59921515ac7e94c9125006f07aaf57`；分支 `codex/frontend-unified-workspace`。本轮本地实现供审查，不推送，不更新 PR，不合并或部署。仅前端、测试、文档，无后端规则或协议改动。

## 行为

删除按 defense 状态调整跨列的规则。普通回合、规则 pending、响应付款、三步防御和最终付款使用相同手牌 dock。

1. **透支**：在自己的原单位/装备上多选，可取消单项；明确完成或跳过，不提前横置/扣费。
2. **防御牌**：点击原技能、绑定技能栏或手牌卷轴单选，自动进入强化。响应使用明确的“选择响应牌”模式，选牌后仍按原付款/确认流程发动。
3. **强化**：在原技能/手牌上多选，明确完成或跳过；有合法可选祭献时提供独立选择入口。最后核对组合、调整付款并一次确认。

三个步骤可返回。改变来源后重验强化/祭献并重新计算付款；取消本地选择只清草稿，不等同“不防御”。不防御始终有一键规则入口。新 revision 或断线清除旧防御选择；保留原提交门禁、在途锁和不重发策略。

当前步骤的原卡点击/Enter/Space 优先于普通菜单，离开防御恢复原行为；悬停详情不变。虚线框表示可选，实线框和摘要表示已选，另有文字与 ARIA 状态。定位按钮滚动到原卡；其他手牌页提供明确切页提示。已有绑定栏直接高亮，不重复列表；仅没有已知原卡入口时使用紧凑兜底。

候选沿用服务器投影的 can_defend/can_defense_boost/can_react、已学/绑定技能、手牌卷轴和既有可透支单位/装备来源。前端不增加卡号或卡文解析，不改规则；后端仍是最终合法性裁决者。防御单选沿用此前 UI，不将本轮扩为服务端多法术组合规则更改。

## 验证

Go 1.26.1，`go test -count=1 ./...`、`go vet ./...`、Node语法/提交状态机/成本测试通过。十项前端脚本通过：match、reactions、quality、fan、primitives、failed_action、usability、card_visibility、defense_workspace、defense_edges。使用两真实客户端与测试房间API布置场景；动作经页面和WebSocket。

全量 `go test -race -count=1 ./...` **失败**：既有 API 全局注册表重注册与旧 WebSocket 广播读竞争再次复现；game、match 等包通过。没有修复或掩盖该竞争。详细输出见 [validation.txt](validation.txt)。

限制：仅电脑端1440/1366/1024完成视觉复核；长绑定栏、候选与场面仍需局部滚动，未声称全部728张卡组合穷举。移动端没有新验收。卡图与描述内小图标仍受外部网络影响。纯响应/其他规则 pending 保留原通用候选界面，本轮只替换防御选牌，不扩大其他机制。
