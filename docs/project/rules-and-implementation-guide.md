# 当前规则与实现说明

本文档用于本次 PR 的规则说明，也给后续 GPT agent 提供项目上下文。若与代码冲突，优先检查代码和测试；若与 `docs/rules/core-rules.md` 冲突，优先请规则作者确认。

## 项目目标

当前目标是让基础包在浏览器双人对局中可玩、可测、可继续迭代。运行时只支持基础包，不支持扩展包。

卡牌行为必须由 Go 代码显式实现。中文卡牌文本、JSON 快照和文档用于人类阅读、审计和生成定义，不能作为运行时解析效果的来源。

## 本次 PR 的主要规则更新

### 1. 规则文档化

新增并整理：

- `docs/rules/core-rules.md`：玩家可读的核心规则。
- `docs/rules/glossary.md`：术语表。
- `docs/rules/card-text-style-guide.md`：卡牌文本表述规范。
- `docs/project/current-runtime.md`：当前运行方式说明。
- `docs/project/card-data-workflow.md`：卡牌数据更新流程。
- `docs/project/development-guidelines.md`：后续开发要求。
- `docs/project/rules-implementation-audit.md`：规则实现审计。

核心原则：

- 未写“可以”的触发/效果默认强制。
- 写“可以”的触发或执行部分是可选。
- `祈咒` 只定义时机，不定义强制性。
- `主动`、`条件`、`光环`、`强制`、`可选` 是卡牌文本审计分类，不代表可以解析文本自动执行效果。

### 2. pending action 和前端窗口

本轮修复了多个前端卡死点：

- pending action 只对目标玩家显示完整内容。
- 非目标玩家显示等待状态，不会误弹选择窗口。
- pending action 到达时关闭可能遮挡它的临时覆盖层。
- emergency pending 面板作为兜底渲染，避免检索、反制、祈咒等窗口丢失。
- 水占术在 emergency pending 中仍可排序、置顶、置底和选择检索目标。
- 静态文件设置 no-cache，避免本地测试时浏览器继续使用旧版 `game.html`。

### 3. 反制

反制类道具现在遵循以下流程：

1. 主阶段免费盖放到装备区。
2. 满足触发条件时，对拥有者打开是否发动窗口。
3. 选择发动时支付费用，可在对手回合用透支支付。
4. 发动后根据具体卡牌取消原行动或继续原行动。

前端需要看到 `pending_action.player_id`，并且只让目标玩家操作。

### 4. 祈咒和回合开始效果

祈咒效果在回合开始触发，不应作为手动回合技按钮出现。

强制/可选判断：

- 文本没有“可以”：默认强制触发并执行。
- 文本写“可以”：前端打开选择窗口或允许跳过。

### 5. 法术响应

冰封消解、风洞、虹吸等响应牌通过 `SpellReactionBehavior` 显式实现。

前端响应入口显示规则：

- 处于防御窗口。
- 该牌 `can_react == true`。
- 若是技能，必须竖置且无冷却/石化等限制。
- 若当前元素不够，但选择可透支来源后可以支付，也应显示响应入口。
- 点击响应时，如果还没选择足够透支来源，则提示玩家先选择透支单位。

### 6. 防御窗口

防御方可以同时选择：

- 防御技能。
- 防御法术卷轴。
- 防御强化技能。
- 透支来源。

费用合并后一次性支付。透支只支付本次防御，不保存多余负载。

防御成功条件：

- 攻击威力小于等于 0；或
- 至少选择一个防御来源，且防御威力大于等于攻击威力。

### 7. 解咒

解咒中的“防御法术”是规则关键词含义，不是泛指所有防御行为。当前可被解咒取消的来源包括：

- 带防御用途的技能。
- 防御法术卷轴。

解咒取消一个防御来源后，防御窗口继续结算剩余来源。

### 8. 法术卷轴

法术卷轴是消耗品，但打出效果相当于打出一个法术。

运行时用显式卡号集合识别基础包法术卷轴，不从 `Description` 或 `Tag` 字符串推断行为。

攻击型法术卷轴：

- 从手牌使用。
- 支付入场/使用费用。
- 若需要目标，必须指定法术目标。
- 打开防御窗口。
- 以自身 `Power` 作为威力，以自身 `Attack` 作为命中伤害。
- 命中后结算范围、状态和具体命中效果。

防御型法术卷轴：

- 只能在防御窗口从手牌选择。
- 支付费用后提供防御威力。
- 结算后进入弃牌堆。

重要例子：

- 灼烧卷轴：命中目标后给命中目标点燃1，不再打开任意点燃目标选择。
- 水形之束卷轴：作为法术命中后横置命中的敌方伙伴。
- 雷暴卷轴：按范围命中并给仍在场的命中单位眩晕。
- 连锁闪电卷轴：按法术造成伤害，命中后抽牌。
- 噬魂卷轴：命中后打开削弱目标选择。

## 后续 agent 注意事项

1. 不要从中文描述文本推断运行时效果。
2. 不要把扩展包加入运行时卡池，除非项目范围明确改变。
3. 行为判断必须考虑卡牌实例状态，不要只看 Go interface 静态实现。
4. 反制、响应、祈咒、检索都可能打开 pending action。前端必须处理目标玩家可见性。
5. 防御透支不是消耗。
6. 法术卷轴是消耗品，但结算应走法术路径。
7. `直接攻击` 和 `法术攻击` 是两套不同结算。
8. 修改 `web/game.html`、pending action、WebSocket 状态或防御流程后，必须做浏览器级验证。
