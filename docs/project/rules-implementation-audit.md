# 规则实现审计

本文档记录当前代码与新版核心规则的吻合情况。它面向开发者和后续 agent，不替代玩家可读规则书；玩家规则以 `docs/rules/core-rules.md` 为准。

## 总体结论

当前基础包框架已经支持真实双人前端对局，并覆盖了本轮规则重建中最重要的通用流程：

- 双方人物、3x3 单位区、技能区、装备区、技能池、手牌、弃牌堆和元素池。
- 主阶段召唤、学习技能、装备、盖放反制、消耗、攻击、使用道具和施放法术。
- 法术攻击、防御窗口、防御强化、响应法术、解咒、防御透支和命中结算。
- 反制道具的盖放、触发询问、费用支付、透支支付、取消或继续原结算。
- 回合开始祈咒、条件触发、检索/排序 pending action、回合结束弃牌与重置。
- 法术卷轴作为“打出一个法术”的特殊消耗品处理。

仍需长期演进的部分：

- 统一触发队列和同一时点多触发排序。
- 更完整的光环模型。
- 更细的前端自动化 E2E 覆盖。
- 扩展包卡牌暂不纳入运行时支持范围。

## 已确认规则与实现

### 区域与朝向

- 人物和伙伴是单位，位于 3x3 单位区。
- 人物开局在己方单位区中心，竖置入场。
- 伙伴、装备、技能默认横置入场，除非关键词或效果改变。
- 技能区和装备区各有容量限制。技能替换时旧技能返回技能池；装备替换时旧装备进入弃牌堆。

### 元素支付

- 奥术/无费用是通配需求，支付可以由任意元素满足。
- 当支付存在歧义时，前端应让玩家显式选择支付方式。
- 透支只用于防御/响应等窗口支付本次费用。透支会横置所选单位或装备，不会把多余负载存入元素池，也不会触发“消耗”效果。

### 消耗

- `消耗:` 是把竖置来源横置作为费用。
- 横置卡不能支付消耗费用。
- 防御透支不是消耗。
- 普通装备/单位消耗获得负载；反制道具揭示支付不等同于消耗。

### 回合时序

回合开始：

1. 当前玩家成为回合玩家。
2. 处理回合开始触发，包括祈咒。
3. 若未被效果跳过，抽牌。
4. 进入主阶段。

回合结束：

1. 弃牌至手牌上限。
2. 重置己方卡牌。
3. 结算并移除应在回合末处理的标记。

冷却和冻结会阻止本次重置，然后再减少标记层数。

### 祈咒

- `祈咒` 只表示触发时机是回合开始。
- 是否强制取决于文本。写“可以”则为可选；未写“可以”默认强制。
- 祈咒不应显示为手动回合技按钮。

### 法术、防御和响应

- 攻击法术进入防御窗口。
- 防御方可以选择防御技能、防御法术卷轴、强化技能，以及用于支付的透支来源。
- 防御威力大于等于攻击威力且至少选择一个防御来源时，防御成功。
- 响应法术如冰封消解、风洞、虹吸在防御窗口作为独立响应入口显示。
- 响应费用可以使用透支支付；前端应在“可透支后可支付”时显示响应入口。

### 解咒

`解咒` 中的“防御法术”不是泛指所有用于防御的牌，而是特指具有“防御”规则含义的防御法术来源。目前包括：

- 带防御用途的技能。
- 写有防御含义的防御法术卷轴。

解咒取消被选择的防御法术来源后，再继续防御结算。

### 反制

- 反制类消耗品可以在主阶段免费盖放，面朝下放入装备区并占用装备槽。
- 当触发条件满足时，拥有者收到是否揭示并发动的询问。
- 选择发动时再支付印刷费用；对手回合也可用透支支付。
- 反制可以取消原行动，也可以在原行动继续前/后施加效果，取决于具体反制。
- 若不发动，原行动继续。

### 法术卷轴

法术卷轴是标签为“法术卷轴”的消耗品，但运行时不解析标签文本；代码使用显式卡号集合识别基础包法术卷轴。

攻击型法术卷轴：

- 从手牌使用并支付其费用。
- 需要目标的卷轴必须先选择法术目标。
- 打出后进入法术防御窗口。
- 使用自身威力、攻击力、范围和关键词进行法术命中结算。
- 命中效果在命中后对命中单位生效。
- 例：灼烧卷轴的“点燃1”表示命中目标后获得点燃1，而不是另开任意点燃目标选择。

防御型法术卷轴：

- 不可在主阶段普通使用。
- 在防御窗口从手牌作为防御来源选择。
- 支付费用后提供防御威力，结算后进入弃牌堆。
- 可以被解咒视为防御法术来源取消。

### 直接攻击

- 直接攻击不同于法术攻击。
- 直接攻击没有命中概念，也不触发法术命中效果。
- “直接攻击不可防御”不影响法术防御窗口。
- 狂乱符文等强制直接攻击效果应锁定由有攻击力的单位执行，不由法术执行。
