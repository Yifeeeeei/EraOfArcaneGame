# PR 描述草稿

## 标题

重建基础包规则框架、卡牌行为和前端交互窗口

## 背景

本 PR 基于新版规则校对和基础包卡牌文本整理，对当前游戏框架做一次集中重建。目标是让基础包在真实双人前端对局中更稳定地测试，并把规则、卡牌文本规范、实现边界和后续 agent 工作方式沉淀成文档。

运行时范围仍限定为基础包。卡牌行为继续由 Go 代码显式实现，不从中文描述文本解析效果。

## 规则与文档

新增/整理了以下文档：

- `docs/rules/core-rules.md`：当前核心规则，面向玩家阅读。
- `docs/rules/glossary.md`：术语表，统一区域、对象、时机和关键词。
- `docs/rules/card-text-style-guide.md`：卡牌文本表述规范，加入主动、条件、光环、强制、可选等分类原则。
- `docs/project/current-runtime.md`：当前运行方式说明。
- `docs/project/development-guidelines.md`：后续开发要求。
- `docs/project/card-data-workflow.md`：卡牌数据更新流程。
- `docs/project/rules-implementation-audit.md`：规则与实现吻合度审计。
- `docs/project/rules-and-implementation-guide.md`：给 reviewer 和后续 GPT agent 的规则/实现说明。

核心规则澄清：

- `祈咒` 只表示回合开始触发时机，不等于强制。是否可选取决于文本是否写“可以”。
- 未写“可以”的触发或效果默认强制。
- 防御透支不是消耗，不触发消耗效果，不保存多余负载。
- 直接攻击和法术攻击是不同结算。
- 解咒中的“防御法术”特指具有防御用途的法术来源，不泛指任何防御行为。
- 法术卷轴是消耗品，但打出效果按法术处理。

## 主要实现更新

### 后端

- 重建 pending action 可见性：只有目标玩家收到完整可操作 pending action，非目标玩家只等待。
- 修复反制道具流程：盖放、触发询问、支付费用、透支支付、取消或继续原行动。
- 修复祈咒时机：祈咒在回合开始触发，不作为手动回合技按钮。
- 扩展防御窗口：支持防御技能、防御卷轴、强化技能和透支来源一次性选择。
- 修复响应法术：冰封消解等响应可以在防御窗口显示，并允许用透支支付。
- 接入法术卷轴：
  - 攻击型卷轴从手牌使用后进入法术防御窗口。
  - 卷轴使用自身威力/攻击/范围/状态作为法术结算。
  - 命中效果在命中后对命中单位生效。
  - 防御型卷轴只能在防御窗口作为防御来源使用，结算后进入弃牌堆。
- 修复多个基础包卡牌行为，使其符合新版规则。
- 添加/更新大量规则回归测试和基础包 smoke 测试。

### 前端

- pending action 加入缓存和 emergency fallback，减少检索、反制、祈咒窗口丢失导致的卡死。
- 水占术 pending UI 保留排序、置顶、置底和检索选择。
- 防御窗口显示响应法术、透支支付、普通防御技能、防御卷轴和强化技能。
- 法术卷轴在手牌中使用时，按法术目标选择而不是任意效果目标。
- 静态文件 no-cache，降低本地测试使用旧版 `game.html` 的概率。

## 法术卷轴规则说明

法术卷轴通过显式卡号集合识别，不解析描述或标签文本。

攻击型法术卷轴流程：

1. 玩家从手牌使用卷轴并支付费用。
2. 若需要目标，必须选择合法法术目标。
3. 后端创建 `PendingSpell` 并打开防御窗口。
4. 防御方可防御、响应或不防御。
5. 若命中，按卷轴攻击力造成伤害，并按卷轴范围/关键词/命中行为结算。

例子：

- 灼烧卷轴：命中目标后点燃1，不再另开任意点燃目标选择。
- 水形之束卷轴：命中后横置目标伙伴。
- 雷暴卷轴：范围命中并对仍在场的命中单位施加眩晕。
- 连锁闪电卷轴：作为法术造成伤害，命中后抽牌。
- 噬魂卷轴：命中后打开削弱目标选择。

防御型法术卷轴流程：

1. 对手法术打开防御窗口。
2. 防御方从手牌选择防御卷轴。
3. 卷轴费用与其他防御费用合并支付，可使用透支。
4. 卷轴提供防御威力。
5. 结算后进入弃牌堆。

## 给后续 GPT agent 的注意事项

- 不要从 `Description` 文本推断运行时机制。
- 行为判断要看卡牌实例状态，不要只看 Go interface 静态实现。
- 反制、响应、检索、祈咒都可能打开 pending action，前端必须处理目标玩家可见性。
- `消耗` 和 `透支` 是不同机制。
- 法术卷轴是消耗品，但结算要走法术路径。
- 修改 `web/game.html`、WebSocket 状态、pending action 或防御流程后，需要浏览器级验证。
