# 前端机制覆盖台账

基线与运行方式见 [设计说明](frontend-design.md)。这里区分“真实 UI 入口已接入”与“已逐一自动化验证”，不以 Go 单测代替视觉验证，也不宣称 728 张卡的全部组合已穷举。

| 机制 | 统一入口 / 原语 | 验证与边界 |
| --- | --- | --- |
| 起手换牌 | 工作区保留/全换 → 草稿确认 | 双真实客户端保留起手；全换入口保留 |
| 消耗、元素分配 | 点击单位 → 工作区消耗 → 可选获得元素 → 草稿 | 真实消耗；选择、费用显示沿用引擎字段 |
| 召唤、地形、吞噬 | 手牌 → 吞噬候选 → 格子目标 → 付款 → 草稿 | 原全功能路径迁移；后端召唤/吞噬回归；非所有卡组合 UI 穷举 |
| 装备、替换、盖反制 | 手牌/替换候选 → 付款/免费盖放 | 反制实际盖放验证；新增真实同类装备替换检查 |
| 技能学习/替换/绑定 | 技能池学习按钮、替换候选；绑定仍在宿主详情和可用技能集合 | 真实学习；绑定来源保留，未错误进入技能池；替换/全部绑定卡组合未逐一卡 UI 验证 |
| 攻击 | 点击单位 → 工作区攻击 → 合法目标 → 草稿 | 原合法性适配保留；后端范围/引魔等全量测试 |
| 目标/区域法术 | 战场目标、范围预览、确认前目标位置汇总 | 真实雷击、闪电链及追加目标；所有区域类型通过既有能力字段渲染，未逐个无头点选 |
| 无目标法术、强化 | 选技能 → 调整强化 → 准备施放 → 付款 | 真实红月；不再选择无目标技能后立即发送 |
| 追加目标 | 当前声明的本地目标草稿 | 闪电链真实两目标；不会提前选择服务器未来队列 |
| 付款、透支 | 原费用规划器 + 当前透支可用池 + 增减/重置/确认 | 两客户端反制、响应和防御付款；原始错误留在工作区，执行报错同步新版本后重新选择；严格奥术/特殊替代仍以服务器校验为准 |
| 反制、嵌套选择 | 当前 private pending 的候选/可选放弃 | 双奥术符文：发动一张 → 法术选择 → 放弃下一张 → 继续防御；等待方无候选/盖牌名称 |
| 响应 | 先选响应，付款与最终确认 | 冰封消解真实响应；点击响应卡不发送；继续原防御窗口 |
| 防御/不防御 | 来源、强化、透支、付款、明确规则选择 | 两客户端真实付费防御与不防御，原回合恢复 |
| 主动/诱发能力 | 能力按钮 → 通用候选/模式/付款 | 预知宝珠、血沙主动；两猩红之翼连续诱发，首目标死亡后刷新候选 |
| 检索、弃牌、回收、复活、复制、控制转移 | 服务器提供候选（实例/控制方/区域/状态）→ 通用选取 | 真实超限弃牌；同名实例仍可区分；其余专属卡沿用原规则，运行既有完整 Go 套件；UI 未逐卡穷举 |
| 排序 | 上/下移动 + 放顶/放底 + 确认 | 真实预知宝珠 top_order/bottom_order；有不可检索候选也能排序 |
| 伤害/层数分配 | distinct candidates + allocations 整数映射 | 真实波纹 2+1 分配；Go 测试校验总数/非整数/错误不调用回调；适配四个原有分配来源 |
| 负载重分配 | 每个选中实例的元素数量 | 真实自然交感 2 个伙伴负载从 2/1 改为 1/2 |
| 负载/生命分配 | 数量 + 支付模式 | 真实血沙双方付款交接；前端检查上限/可支付量；既有卡牌 callback 的全面事务回滚不是本次协议承诺 |
| 状态、附属、卡下方 | 名称/状态文字与卡牌详情 | 绑定技能原入口保留；本次复核补上此前遗漏的 under_cards/attached_behaviors 详情；真实星落收纳/检视通过，未遍历全部附属组合 |
| 回合末、终局 | 结束回合仍走统一确认；选择完成后才推进 | 弃牌交接、双方和局终局；余火等原流程 Go/API 回归保留 |
| 对局记录 | 服务器公开事件独立记录，本地操作另收起 | 只格式化收到且广播给双方的事件；未知事件保留通用记录，不发布结算帧树；非持久历史 |
| 断线/重试/重复点击 | 单在途状态机、手动同步、版本前置条件 | Node 测试 state-before-ack、旧回执、相同窗口、未知结果；真实 UI 执行拒绝后同步重选、执行前拒绝保留草稿、双击和断线重连不自动重发 |
| 观战/隐藏信息 | 公开视图 + 通用等待上下文 | Go 检查对手/观众无 private candidate/prompt/counter type；真实等待方 DOM 检查 |

## 完成与保留限制

- 生产 JS 不再按卡号、名称、描述决定交互。少量既有特殊准备能力仍在后端投影边界映射；这次没有重写它们的规则实现。扩展 UI 原语时需要更新显式协议和测试。
- 静态盘点发现 289 种命名选择创建点（见 [清单](frontend-decision-inventory.md)）；常规选卡/选位置/模式统一由候选数据驱动。静态扫描不证明动态生成窗口或全部规则组合正确。
- 新页要求同分支新增 revision/ui 协议；旧服务器请使用独立 legacy 页。旧客户端兼容意味着不能把 expected_revision 校验称为全服务幂等。
- 底层 callback 若本身先变更后返回错误，前端无法提供事务回滚；本次不扩大为引擎重写。没有持久请求去重和断线自动重放。
- 视觉检查覆盖 1440×1000 与 390×844；手机使用纵向滚动和导航，未在真机、所有浏览器或读屏器上验证。触控入口已提供；全面 WCAG 审计未开展。
- 卡图/外部字体仍需网络。云端截图使用真实 raw 仓库卡图，原 Pages 域名在当前云环境不可达；不以 API 通过代替图片/布局检查。
- 实现完成时未推送或创建 PR；后续按用户授权交付草稿 PR，见 [交付材料](review/frontend-f2b78f5/README.md)。不合并、不部署；完整旧版页面保留短期回退。
